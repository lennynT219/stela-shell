## Current decisions

- Keep a shared TypeScript runner for assignment input, bounded JSON parsing, deadlines and results. `processes.ts` owns platform-specific launch and termination. Do not replace Pi or reimplement its conversation loop.
- POSIX retains a separate process group and SIGTERM/SIGKILL escalation. Cleanup also runs on leader exit so inherited pipes cannot indefinitely prevent close. No Rust executable is required on POSIX.
- Windows 10+ uses the Rust controller in `native/windows-job/` with locked `windows-sys` dependencies. Create the process suspended with atomic Job assignment, verify containment before resume, inherit only stdio, and never expose the Job handle to children. Missing helper or failed Job setup must fail closed, not fall back to taskkill or an uncontrolled process.
- Windows cancellation terminates the controller and closes its KILL_ON_JOB_CLOSE Job; it does not emulate graceful POSIX signals. Normal completion waits for an empty Job, and the controller monitors abrupt parent death.
- Build the Windows artifact explicitly with `npm run build:windows-helper`. The runner resolves it from the extension's real checkout, including when a development link is used. Runtime delegation must never install, download or compile it. Build artifacts are ignored; Cargo.lock remains source-controlled input.
- Preserve bounded read-only assignments, the default/maximum of five children, 12 model turns, 32 reader calls, queue ownership and inherited permission hooks. Children cannot delegate or modify project files. No npm dependencies are added.
- Execution control: optional integer `timeout_seconds` is normalized to 120 and restricted to 120–300. Admission freezes the budget; exact active duplicates keep their original ID and budget even if a different timeout is requested. Do not extend active work or retry automatically. Keep already emitted nonempty public text, including JSON streaming text, within 8 KiB; failed/cancelled output is explicitly partial in model delivery and human inspection. Only an authoritative nonempty final answer can complete. Retain bounded numeric read offset/limit metadata, not source contents, and add no mandatory progress turns or performance instrumentation.
- Instruction ownership: refine existing handoff guidance into coherent, independently useful questions, not a child per file or fixed workflow. Keep the parent's integration role and use runtime enforcement rather than duplicating operational rules throughout FARO and tool/helper prompts.
- GitHub SSH pushes from this agent session remain unavailable (`Permission denied (publickey)`), despite successful manual pushes by the user. A manual push does not establish that this session can authenticate. Do not retry the denied action or change credentials, identity or transport to bypass it; publication needs an authenticated user terminal or an explicitly resolved session prerequisite.
- Proactive delegation is a FARO decision within the user's existing task scope, not a mandatory stage or background scheduler. Use direct tools for simple retrieval; initiate independent evidence work only when separation has a clear benefit, respecting explicit consent requirements. `stela_delegate` is the dispatch tool; `stela-helper` resolves one bounded read-only question. The parent retains implementation, authorized commands, continuity and result integration.
- Existing continuity decisions remain in FARO: fixed five-section work state, selective persistence rather than prompt history, immediate recording of relevant explicit decisions within authorization, and required persistence before the final response.
