# Imágenes — approved project assets

A primary Pi session can request **one new still image from text**, **one new image guided by 1–3 selected PNG references**, or **an edit to one selected PNG**, through the official TypeScript Codex SDK. The chat model doesn't change. Generation uses Codex on this machine and OpenAI's service with the operator's existing **ChatGPT login**. There is no OpenRouter, API-key mode, paid fallback, automatic login, or gallery.

## From preview to project file

1. **Start with an idea or ask for a result.** «Quiero una portada para un cuento» starts planning. Pi can ask one or two questions if important details are missing. If you only want a draft prompt, ask for the text.
2. **Say what to generate.** «Genera la portada» uses the agreed visual details; «Genera una foto de un gato con alas, sin letras» needs no draft step. Pi writes and sends the prompt without asking you to copy or confirm it. Only a current generation request enables that tool; ordinary brainstorming, a draft or «sí, me gusta» does not. The legacy `Genera la imagen con este prompt:` heading still works if you want to supply the exact wording.
3. **Review or correct the preview.** The numbered result appears in the chat. «Haz las alas más pequeñas» always uses the latest successful preview on the active branch, even after intervening chat, without asking for a number. «Corrige la vista 2: quita el fondo» selects an exact preview on this conversation branch. If Pi asks which one, reply «usa la vista 2» without repeating the correction. The extension revalidates the original PNG; it does not substitute a changed or missing file. A correction creates another preview, not a project write. For preview corrections the chat agent interprets intent in context; no list of command phrases authorizes the edit. The host still binds each call to the current direct turn and an eligible preview. Praise and requests for advice should get conversational replies, not edits. A mistaken interpretation can start a billable edit; nothing is saved automatically. If a preview correction requests the agreed palette, the agent supplies only the known hex colors, not the conversation; missing colors must be clarified rather than guessed. A failed edit adds no preview and does not change which one is latest. No automatic retry, scanning the output directory or choosing a file by recency.
4. Say **«guarda esta»**, **«apruebo la segunda»**, or **«guarda la vista 2 como portada.png»**. `ss_images_save({})` (**Guardar imagen**) takes *no* model-supplied path, filename, selector or approval flag. The live approval selects the exact preview and optional name. If several exist and the immediately preceding conversation doesn't identify a single preview, specify the number or «la última». «Me gusta», a hypothetical instruction or an old approval is not a save order. A direct approval needs no second confirmation.
5. The first approved save creates `media/images/` under **the working directory of this Pi session**, not a Git or Brain root. A readable default name is derived from the description. An occupied `portada.png` becomes `portada-2.png`, then `portada-3.png`; existing files are never replaced. A recorded save is reported instead of creating another copy for the same preview.

Close Pi and reopen **the same conversation** (`pi --continue` or `/resume`): the numbered previews on its active branch remain eligible. A preview descriptor (thread, basename, SHA-256, dimensions, suggested name and owner) is in the Pi tool result's `details`, not a separate index. Approvals live only in memory during the current direct user turn. Other sessions/forks, abandoned branches, changed project directories, `ss-helper`, extension-injected messages and pasted transcripts cannot carry an approval. Ephemeral `--no-session` conversations cannot be reopened. Pi may persist a resized preview in its transcript; saving **never** substitutes that copy if the original changes or disappears.

## Edit a preview with visual guidance

With a preview on the current branch, paste or attach **one PNG** and describe what to transfer. For example, «dale este acabado sin cambiar la forma». Pi receives the caption as chat text, not the selected PNG bytes or clipboard path. Its agent chooses whether to edit the preview using the attachment as guidance, edit the attachment itself, generate a new composition, or just discuss. It cannot inspect the external picture in chat. A guided edit sends the verified preview first and the current reference second to Codex (12 MiB combined). A request for one attribute leaves unrelated features intact; a request for overall resemblance can change the silhouette and proportions. Explicit preservation constraints take priority in either case. No second confirmation or automatic save. If clarification takes another turn, attach only the external PNG again, never the project preview. Explicit headings below keep the caption private from the chat model.

## Use a photo or references

- **Edit an existing photo:** attach or paste one PNG and say «Ponle alas a esta foto».
- **Generate a new composition:** attach or paste one to three PNGs in order and say «En base a esta foto genera un personaje nuevo». The references guide a new image rather than being edited.

**Sending an image with an edit or reference-generation instruction authorizes sending the complete image(s) and instruction to OpenAI via Codex. There is no second confirmation.** This includes people or visible information you ask to remove. Ordinary attachments without an image operation use Pi's normal chat behavior. Do not attach a photo to an image request if you do not want it sent. Saving the result to the project remains a separate step.

- **TUI:** Pi pastes clipboard images as temporary paths. Keep each pasted path separated from the instruction by whitespace, ideally on its own line. To explicitly select other local PNGs, the legacy `Editar foto:` and `Generar con referencias:` headings accept absolute PNG paths on separate lines (no quotes, globs, directories or links). The usual `Genera la imagen con este prompt:` with a selection also routes to reference generation. In **RPC**, attach the PNGs in the current prompt's `images` array; a host path cannot replace an attachment.
- These operations validate and pin the current PNG bytes when you submit, stripping unneeded metadata. Except for the contextual caption described above, the chat model receives only a one-use marker, not the original photo, path or private instruction. It cannot supply different sources, reuse earlier uploads or replay the marker. Only the generated output is returned to the chat. A correction uses a verified generated preview of the active conversation, not a previous upload. This workflow does not hide inputs from your client, terminal or other loaded extensions.
- Codex reads private temporary copies via its SDK. The original is not modified. Selected PNGs must total at most 12 MiB and instructions at most 4096 UTF-8 bytes. An invalid or missing selection does not fall back to another operation. There is no automatic retry. Staged copies are cleaned up on completion, error or cancellation; this does not delete clipboard originals or anything already received or retained by Codex/OpenAI.

## What goes into the visual brief

The brief keeps the requested subject, exact lettering and exclusions intact, and adds the intended format, composition and visual treatment. In the **same** Codex turn, the model translates that brief into a concrete prompt for the image tool; there's no second model call to plan the image. Explicit user choices take precedence over suggested art direction.

If the submitted prompt is for a logo representing SS in the StelaShell checkout, the adapter can explain that StelaShell is a personal AI terminal workspace on Pi, with collaborating agents and memory across sessions. It suggests two paths joining into a terminal prompt as one possible visual metaphor, legible at icon size. These are a short packaged product description and an artistic suggestion, not a read of the repository, Brain or chat history. Name **StelaShell** in full as the subject (e.g. «un logo para StelaShell») to use that reference elsewhere. The shorthand recognition is deliberately conservative: another project, a comparison or an acronym with its own definition should not inherit this identity.

For other subjects, put any meaning the image depends on in the request: **«Genera una portada para Marea, un club de lectura junto al mar; combina un libro abierto con una ola, sin texto»**. If a reference is unknown, Pi should ask what it means. Planning uses the ordinary chat, not a hidden second model; the model prepares only the relevant visual details for the Codex brief, not the Q&A transcript. The questions and creative choices are model-guided; the extension requires a direct current generation request before Codex can run.

## Dependency, login and activation

- The verified host is Pi 1.6.0 on Linux with Node 24. `@openai/codex-sdk` **0.171.0** is pinned in the root manifest and lockfile. Keep npm's platform-specific optional dependencies enabled. There is no global CLI requirement or runtime install. Use the repository's normal dependency install on another machine. See the [official SDK](https://developers.openai.com/codex/sdk/) and [Codex authentication](https://learn.chatgpt.com/docs/auth).
- For first login, from the checkout with its dependencies installed, run `node node_modules/@openai/codex/bin/codex.js login` and choose **Sign in with ChatGPT** in the official flow. `node node_modules/@openai/codex/bin/codex.js login status` should say `Logged in using ChatGPT`. Never paste credentials into Pi. With no matching login, generation stops before starting a model turn. Save-only operations don't require a login, network, or quota.
- The package declares `extensions/images/index.ts`. If the profile uses per-extension development links, load `extensions/images/` through **one** route, then reload Pi. Do not add a link as well as a package registration for the same extension. If the profile has an explicit tool list, allow `ss_images_generate`, `ss_images_generate_with_references`, `ss_images_edit` and `ss_images_save` according to its normal permissions. The extension changes no settings or links.
- This is an operator-initiated local interaction. OpenAI's plan eligibility, quotas and product behavior can change. It is not a subscription-backed public image API or a CI service. It doesn't measure quota or promise that a cancelled or failed generation was free.

## Execution and file boundaries

- No model call at startup. The Codex home and temporary workspace must be outside the project, and the image output directory must not be a symlink. A fresh SDK thread and private working directory outside the project, one `runStreamed()` per direct text generation, direct reference generation or edit. Text-only generation uses an empty workspace and **never attaches files**. The reference or edit action stages only the validated input copies in that private directory and uses generation or editing instructions respectively. No Pi history, Brain or access to the original directories. Staged inputs are removed on normal completion, error or cancellation; cleanup failures are reported. No app-level retries. A user cancellation, owner change or seven-minute deadline is forwarded to the active operation; late results are discarded. Ending a turn, including a failed one, releases the cancellation listener without aborting the finished stream. A Codex error is returned to Pi without a retry. The SDK and its native runtime are trusted programs with normal account-level access to their own auth/session/image storage.
- Before generation, inspect login status and effective config with the **bundled** executable. No manual auth-file reading, credentials in messages, or modifications to user config. Do not forward API-key or provider-routing environment variables. Use the built-in OpenAI provider, a named permissions profile with only read access to the private workspace, no command approvals, shell, web search, view-image tool, apps/plugins, enabled MCP servers or child agents. Both Codex memory feature names (`memories` and its legacy `memory_tool` alias) are disabled for this invocation and checked in the effective configuration; the user's profile is unchanged. Codex merges MCP tables: disable discovered servers per invocation and recheck. Existing managed requirements still apply. Reject incompatible effective configuration (including a legacy `sandbox_mode` overriding the named profile, custom upstreams, instructions, or configured hooks) rather than weakening it. This is not a universal sandbox or a guarantee against compromised local software or simultaneous external configuration changes.
- Accept a **completed** turn with an unambiguous reported path in `CODEX_HOME/generated_images/<new-thread-id>/`. Never scan for a recent image, open arbitrary paths from prose, or copy links. Codex 0.171.0 reports the obsolete `memory_tool` spelling as an `item.completed` error item. The adapter allows its exact deprecation message once, immediately after `thread.started` and before `turn.started`. Any other warning, or the same warning repeated or emitted during a turn, is rejected. This exception does not authorize any operation or count as a successful turn or PNG. The adapter targets the observed path-as-text protocol, not arbitrary future artifact formats.
- Check static PNG framing, pixel data, dimensions and byte bounds (12 MiB, 12 million pixels, 8192 per axis; noninterlaced, 8-bit grayscale/RGB with optional alpha). Ancillary text/profile metadata is not passed to Pi in the preview; **the saved original retains all its bytes**. Re-read and verify the digest before creating any project directory. Publish from a private staging file with a hard link (atomic, no replacement); a filesystem without the necessary primitive gives an error, not an unsafe fallback. On Linux, directory file descriptors anchor file operations. Other platforms also reject redirected directories and compare identities, but this is not protection against a hostile user racing filesystem mutations. Publication and writing the Pi tool result are not a cross-file transaction.

## Checks

`node --experimental-strip-types --test extensions/images/tests/*.test.ts` checks routing, scope, PNG validation, ordered staging, no-replace saving and the packaged Codex binary against a **loopback-only** service with synthetic data. Set `SS_TEST_PI_CLI` to the installed Pi **JS entry point** to exercise Pi RPC: planning then direct generation, automatic correction, private attachments sent without a second confirmation, cancellation, save after reopening and the missing-login path. On Linux with Python 3 the suite also exercises a real Pi terminal on a pseudoterminal, with synthetic clipboard paths and a separate save order. These checks do not spend quota, send user photos or assess a live model's image fidelity.
